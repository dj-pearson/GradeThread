## Session Notes (2026-05-27) — iOS inventory list (US-180)
First real read surface on top of the SwiftData store — Inventory tab
now shows the user's actual items, grouped by stage, searchable,
sortable, pull-to-refreshable.

What landed in ios/GradeThread/Inventory/:
- InventoryStage.swift — maps inventory_items.status values to the
  tab groupings (All / To list / Drafts / Active / Sold / Shipped /
  Returned), mirroring the web TO_LIST_STATUSES + LISTED_STATUSES
  sets. Each stage carries a label, SF Symbol, and empty-state copy.
- SortOption.swift — newest / oldest / bestROI / highestComp / SKU
  natural sort. naturalCompare diffs numeric runs as integers so
  'S-2' lands before 'S-10'. ROI sort handles missing acquired_price
  gracefully (no-cost rows sort to the bottom). Comparator shared
  between the view and the unit tests.
- InventoryFilter.swift — pure apply(stage:search:sort:) runs stage
  cut → search substring → sort in cheapest-first order. Search
  matches title/brand/SKU today; style + container follow once the
  sync engine pulls them.
- InventoryRow.swift — thumbnail (AsyncImage with brand-tinted
  fallback) + title + brand·size + price (listing → target → cost
  fallback via CurrencyFormatter) + status badge with color-coded
  background (green sold/shipped, navy listed, red returned).
- InventoryListView.swift — horizontal-scroll tab chip row with
  per-stage live counts, .searchable in nav drawer, sort menu in
  trailing toolbar, .refreshable triggers a NotificationCenter post
  that ContentView routes into SyncEngine.sync() — keeps the engine
  handle off the view's API surface.

SyncEngine.pull() is no longer a stub:
- Fetches inventory_items + item_photos in two batched requests
  (no RPC; relies on RLS for per-user filtering).
- Builds a primary-photo-per-item map (first by sort_order).
- Merges into LocalInventoryItem applying ConflictPolicy per field:
  title / brand / SKU / notes / measurements / target_price are
  client-wins-if-dirty; status / grade / cost / created+updated are
  server-wins. Measurements JSON-serialize for SwiftData storage.

ContentView:
- InventoryPlaceholder → InventoryListView wired in.
- .onReceive observer for .inventoryPullRequested forwards to
  syncEngine.sync().

Tap on a row pushes ItemCanvasPlaceholder for now — full US-181
canvas with inline editing lands next.

Tests in InventoryFilterTests cover stage status mappings, sort
comparators (newest / bestROI / SKU natural with numeric run
ordering, case-insensitivity, empty strings, missing cost),
InventoryFilter search substring on title/brand/SKU, whitespace
search returning all, and the apply() pipeline composition (stage
→ search → sort).

## Session Notes (2026-05-27) — iOS Live Text fallback (US-177)
On-device OCR fills brand + size when Claude can't read the tag (low
confidence, missing, or full extract failure). No network, works
offline, no AI quota consumed.

What landed in ios/GradeThread/Vision/:
- TagTextRecognizer.swift — actor wrapping VNRecognizeTextRequest at
  .accurate level. Returns [RecognizedLine] with text + confidence +
  bounding box.
- SizeTagInference.swift — heuristic parser. Lowercase whitelist of ~30
  brand tokens catches both UPPERCASE-printed brands and the
  consistently-lowercase ones (adidas, lululemon). Uppercase-ratio
  fallback for unknown brands, with rejections for 'SIZE L' /
  'MADE IN USA' / bare alpha-size tokens. Size detection in priority
  order: waist×length ('W30 L32', '30x32') → explicit 'Size N' →
  bare alpha (S/M/L/XL/XXL/XXXL) → bare numeric (0–60, year guard).

AIExtract integration:
- AIExtractStore.mergeLiveTextSuggestions(brand:size:) — inserts only
  the fields Claude missed, at confidence 0.4 with source 'live-text'.
  Not auto-accepted (below the 0.8 default threshold) — user opts in.
- AIExtractView.runLiveTextFallbackIfNeeded() — pulls the tag-slot
  capture's UIImage and runs the recognizer when brand OR size is
  missing from Claude's result. When Claude's entire extract fails,
  the fallback still runs and a synthetic Result is built from
  whatever Live Text produced — partial recovery beats a hard error.
- liveTextBanner — 'On-device OCR filled in the gaps' surfaces above
  the field list when the fallback fired.
- FieldSuggestionEntry.sourceLabel — 'live-text' source reads as
  'On-device OCR' in the per-row UI.

Tests in SizeTagInferenceTests cover whitelist hits, lowercase brand
catch, uppercase heuristic, size-line rejection, all size patterns
including waist×length precedence over bare alpha, year-vs-size
guard, store merge non-override on existing fields, no-op when
nothing new, and the source label.

## Session Notes (2026-05-27) — iOS background photo upload (US-175)
Uploads survive app backgrounding via a background URLSession bound to
the identifier `com.gradethread.app.photo-uploads`. Cap of 3 concurrent
transfers; everything else queued.

What landed in ios/GradeThread/Upload/:
- PhotoUploadTask.swift — per-photo state value type (phase:
  queued / uploading(progress) / uploaded(publicURL) / failed(error) /
  cancelled). progress, isActive, isTerminal computeds for clean view
  reads.
- PhotoUploadStore.swift — @MainActor @Observable. Lookup by
  (slot, inventoryItemId); pendingTasks / activeCount / per-task
  phase + retry mutators.
- PhotoUploadService.swift — @MainActor class owning the background
  URLSession. enqueueAll(...) writes each JPEG to a temp file
  (background sessions need file-based bodies), schedules an upload
  task with Authorization+apikey+x-upsert headers, promotes queued
  tasks as in-flight ones finish. Delegate is a stateless NSObject
  that bounces every callback to MainActor and looks up the upload
  UUID via a service-owned dict (no shared mutable state on the
  delegate). On success, second-phase insert of an item_photos row
  via supabase-swift with photo_type/storage_path/sort_order matching
  the web. Failures push a LocalPendingMutation(kind=.uploadPhoto)
  carrying enough metadata for SyncEngine to retry on
  connectivity-restored. cancelAll() drops in-flight tasks + clears
  store + sweeps temp files.
- AppDelegate.swift — UIApplicationDelegateAdaptor. The
  `application(_:handleEventsForBackgroundURLSession:completionHandler:)`
  callback is held in the service and invoked from
  `urlSessionDidFinishEvents`, completing the wake-app-to-finish round
  trip the OS expects.

UI wiring:
- App.swift: @UIApplicationDelegateAdaptor + environment injection for
