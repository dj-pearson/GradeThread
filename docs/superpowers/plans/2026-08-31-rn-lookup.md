# RN Number Lookup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a public RN lookup at `/rn/:number` plus a `/tools/rn-lookup` hub with a tag reader, so someone holding a garment can find out who made it and then watch our AI read their label.

**Architecture:** Mirrors the shipped Lululemon style-code family exactly. Pure shaping in an edge lib, two anonymous JSON endpoints, a Cloudflare Pages Function that edge-SSRs one page per number, its own sitemap segment, and a React hub in the SPA carrying everything interactive. The database tables already exist and are unchanged.

**Tech Stack:** Deno + Hono (edge service), Cloudflare Pages Functions (SSR), React 19 + Vite + Tailwind v4 (SPA), Supabase Postgres, Vitest (web) and `deno test` (edge).

**Spec:** `docs/superpowers/specs/2026-08-31-rn-lookup-design.md`

## Global Constraints

- **No migration.** `registered_number_registry` (00502) and `registered_number_sightings` (00501) already exist with every column needed. Do not add one, and do not bump `EXPECTED_SCHEMA_VERSION`.
- **Do not edit migration `00466`.** It says the FTC RN database is "auth-gated", which is wrong. Applied migrations are immutable; the correction goes in the seeder header and in the vault note from Task 8.
- **No FTC account, ever.** Read only `https://www.ftc.gov/rn-database/search?search=<term>`, signed out. Never create, log into, or automate an account on `rn.ftc.gov`.
- **Pace FTC requests at one per 2 seconds**, single-threaded, and stop the run on any non-200.
- **`indexable` is computed once**, in the edge lib, and both the page and the sitemap read it from there. A sitemapped URL that renders `noindex` is the failure this family exists to avoid.
- **An RN names the company, not the brand.** No page, title, description or JSON-LD may state or imply that an RN proves a brand or proves authenticity.
- **`no_reference` is not a negative signal.** Copy for an unresolved number never reads as "this RN is wrong".
- **Copy rules:** no em dashes, ASCII punctuation only in code and markup. See `vault/40-growth/copy-style-guide.md`.
- Run `npm run verify` before the final commit. Edge work also runs `cd services/edge-functions && deno test src/tests/<file>`.

- [ ] **Step 4: Implement the parser**

Parse the results table with regexes over the row markup rather than a DOM library, the way `blog-render.ts` already handles HTML in this repo. Read the fixture first and match its actual column order: Type, No., Legal Business Name, Product Line.

```ts
// services/edge-functions/src/lib/ftc-rn-search.ts
// The FTC public RN search, read signed out.
//
// WHY THIS IS ALLOWED, recorded here because it will be questioned:
// the Rules of Behavior at rn.ftc.gov govern ACCOUNTS, which exist so a
// business can apply for, update or cancel its own RN. That system's landing
// page says a login is needed "only if you wish to update or cancel the RN".
// The search lives on ftc.gov, takes a query string, and returns server-
// rendered HTML with no session. We create no account and bypass nothing.
//
// CORRECTION: migration 00466 says this database is auth-gated. It is not, and
// that mistake is why only six brands carry a seeded RN today.

export interface FtcRnRecord {
  kind: "RN" | "CA";
  digits: string;
  legalName: string;
  productLines: string[];
  sourceUrl: string;
}

const FTC_SEARCH = "https://www.ftc.gov/rn-database/search";

export function ftcSearchUrl(term: string): string {
  return `${FTC_SEARCH}?search=${encodeURIComponent(term)}`;
}

const ROW_RE = /<tr[^>]*>([\s\S]*?)<\/tr>/gi;
const CELL_RE = /<t[dh][^>]*>([\s\S]*?)<\/t[dh]>/gi;

function cellText(html: string): string {
  return html
    .replace(/<[^>]+>/g, " ")
    .replace(/&amp;/g, "&").replace(/&#039;|&#39;/g, "'")
    .replace(/&quot;/g, '"').replace(/&lt;/g, "<").replace(/&gt;/g, ">")
    .replace(/&nbsp;/g, " ")
    .replace(/\s+/g, " ")
    .trim();
}

/** Pure: the caller does the fetching, so every rule here is testable.
 *
 *  Never throws on unexpected markup. An empty list is the honest answer and
 *  the seeder reports it as "no match" rather than dying halfway through a run.
 */
export function parseFtcResults(html: string): FtcRnRecord[] {
  const out: FtcRnRecord[] = [];
  for (const row of html.matchAll(ROW_RE)) {
    const cells = [...row[1].matchAll(CELL_RE)].map((c) => cellText(c[1]));
    // Columns, in the order the fixture shows them:
    // Type | No. | Legal Business Name | Product Line
    if (cells.length < 3) continue;
    const kind = cells[0].toUpperCase();
    if (kind !== "RN" && kind !== "CA") continue; // header and filter rows
    const digits = cells[1].replace(/\D/g, "").replace(/^0+/, "");
    if (!digits) continue;
    out.push({
      kind,
      digits,
      legalName: cells[2],
      productLines: (cells[3] ?? "").split(/\s{2,}|,\s*/).filter(Boolean),
      sourceUrl: "",
    });
  }
  return out;
}
```

Read the committed fixture before trusting the column order above. If the real
markup splits product lines into separate elements rather than one cell, adjust
`productLines` and keep the tests as the contract.

```ts

/** One request. The seeder paces the calls; this does not. */
export async function searchFtc(
  term: string,
  fetcher: typeof fetch = fetch,
): Promise<FtcRnRecord[]> {
  const url = ftcSearchUrl(term);
  const res = await fetcher(url, {
    headers: { "user-agent": "GradeThread RN seeder (support@gradethread.com)" },
  });
  if (!res.ok) throw new Error(`FTC search ${res.status} for ${term}`);
  return parseFtcResults(await res.text()).map((r) => ({ ...r, sourceUrl: url }));
}
```

```ts
// services/edge-functions/scripts/seed-registered-numbers.ts
//
// Fill registered_number_registry from the FTC public search.
//
//   deno run --allow-net --allow-env scripts/seed-registered-numbers.ts --dry-run
//   deno run --allow-net --allow-env scripts/seed-registered-numbers.ts --limit 25
//
// Order: brand_knowledge names first, then unresolved sightings by count.
// A brand with two or more FTC matches is NEVER written. A wrong company name
// under a page that claims provenance is worse than a blank one.

export type SeedDecision =
  | { action: "write"; record: FtcRnRecord }
  | { action: "review"; reason: string }
  | { action: "skip"; reason: string };

export function decideSeedRow(brand: string, results: FtcRnRecord[]): SeedDecision {
  if (results.length === 0) return { action: "skip", reason: "no FTC match" };
  if (results.length > 1) {
    return { action: "review", reason: `${results.length} FTC matches for ${brand}` };
  }
  return { action: "write", record: results[0] };
}
```

The runner reads `brand_knowledge` (name, brand_key), calls `searchFtc` with a 2000 ms sleep between calls, and upserts `registered_number_registry` on `registry_key` with `company_name`, `brand_keys`, `source_url`, `verified: true`, `resolved_by: "ftc-seed"`. `--dry-run` prints the decisions and writes nothing. Print a one-line summary: written, review, skipped.

- [ ] **Step 3: Implement both endpoints**

The lookup parses with `parseRegisteredNumber` and 400s when that returns null. It then reads `registered_number_registry` by `registry_key` and `registered_number_sightings` by the same key for the count, resolves `brand_keys` to display names from `brand_knowledge`, and returns `publicRegisteredNumber(...)`. Add a test asserting a CA row never reaches the returned set.

**Tenant isolation:** both tables are global reference data with no owner column, in the same class as `style_code_names`. No `user_id` scoping applies. Record that in a comment above each handler so a future audit does not read the missing filter as a bug.

## Deviation from the spec, and why

The spec put the tag reader "on the hub and on every RN page". It is on the hub only, and RN pages link to it with the number prefilled. The `/rn/:number` pages are edge-SSR'd static HTML, and the shipped style-code family already splits exactly this way: `/style/:code` is static, and the interactive submit box lives in the React hub at `src/pages/marketing/style-code-lookup.tsx`. Putting a vanilla-JS uploader into the SSR body would be a second pattern for one feature.
