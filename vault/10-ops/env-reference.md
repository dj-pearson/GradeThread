# GradeThread + FlipDesk — Environment Variable Reference (master index)

> **Quick index of every env var the codebase reads, and *where it goes*.**
> Generated by scanning the repo (`Deno.env.get` in the edge service,
> `import.meta.env.VITE_*` in the frontend, `env.*` in Cloudflare Pages
> Functions, `process.env` in build/ops scripts, GoTrue/Infisical in CI).
> For **where to obtain** a value and deeper notes, see [`ENVIRONMENT.md`](ENVIRONMENT.md).

## Where things run (the "destinations")

| Destination | What runs there | How vars are set |
|---|---|---|
| **Cloudflare Pages — build** | Vite build of the React SPA | Pages → Settings → Environment variables (build). Only `VITE_*` reach the browser. |
| **Cloudflare Pages — Functions** | Edge-SSR Pages Functions in `functions/` (certs, blog, sitemaps, OG images) | Same Pages env; read at request time as `context.env`. |
| **Coolify — edge service** | Deno/Hono API at `functions.gradethread.com` | Coolify → service → Environment Variables. Server secrets — never `VITE_`. |
| **Supabase — GoTrue auth** | Self-hosted auth container | GoTrue env vars on the `auth` container (`GOTRUE_*`). |
| **Supabase — local CLI** | Throwaway local stack (`supabase start`, `npm run verify:db`) | `supabase/config.toml` reads a few `SUPABASE_AUTH_*`. Never touches prod. |
| **Infisical — iOS prod** | iOS release build (`.github/workflows/ios-release.yml`) | Infisical `prod` env, pulled into the macOS runner. |
| **GitHub Actions secrets** | CI workflows | Repo → Settings → Secrets and variables → Actions. |
| **Local / CI shell** | Ops + maintenance scripts (`scripts/**`) | Your shell / CI step env; not a deployed surface. |

Legend: ✅ required · 🟡 required for that feature · ⬜ optional · 🔒 secret (never client-side).

### Branded auth emails — GoTrue "Send Email" hook

By default GoTrue sends signup-confirmation / password-reset / magic-link /
email-change mail itself over `GOTRUE_SMTP_*` with built-in templates. To send
them branded, through the same transactional pipeline, and carrying a 6-digit OTP
plus a confirm link that lands on the **frontend** (never `api.gradethread.com`),
enable the hook so GoTrue POSTs to the edge instead:

| Setting | Env var (self-hosted `auth` container) | Value |
|---|---|---|
| Enable send-email hook | `GOTRUE_HOOK_SEND_EMAIL_ENABLED` | `true` |
| Hook endpoint | `GOTRUE_HOOK_SEND_EMAIL_URI` | `https://functions.gradethread.com/api/auth/hooks/send-email` |
| Hook signing secret(s) | `GOTRUE_HOOK_SEND_EMAIL_SECRETS` | `v1,whsec_<base64>` (pipe-separate two during rotation) |

Then set the **same** secret as `AUTH_EMAIL_HOOK_SECRET` on the edge container —
`routes/auth-hooks.ts` returns 500 if it is unset. Generate with
`openssl rand -base64 32` and wrap as `v1,whsec_<that>`.

With the hook on, GoTrue stops using its own SMTP for these emails; they flow
through the edge service to SES. Delivery still depends on SES being out of
sandbox — the hook changes rendering and routing, not deliverability.

### Web push (VAPID, US-1901)

| `VAPID_PUBLIC_KEY` | Optional | P-256 public key, served via `GET /api/push/vapid-public-key`. Must equal the frontend `VITE_VAPID_PUBLIC_KEY`. |
| `VAPID_PRIVATE_KEY` | With the public key | Signs the RFC 8292 VAPID JWT. **Secret.** |

## Corrections — what `ENVIRONMENT.md` got wrong

Verified against the code on 2026-07-19. These are recorded rather than quietly
deleted, because anyone who provisioned production from that document acted on
them.

**1. Email was never Resend.** `ENVIRONMENT.md` had a section "Email — Resend"
documenting `RESEND_API_KEY`. **There is no Resend code in the repo.** The edge
service uses SMTP via denomailer with an optional AWS SES v2 HTTP transport
(`lib/email.ts`, `lib/ses-api.ts`, `lib/email-transport.ts`; `EMAIL_TRANSPORT`
selects `smtp` or `ses_api`, defaulting to SMTP). `RESEND_API_KEY` is read
nowhere. Anyone following that section would have provisioned an unused vendor
and configured no working mail path.

**2. eBay was not "stubs returning 501".** That section predates the integration.
`flipdesk-ebay.ts` is fully wired — OAuth with AES-GCM refresh, Inventory
create/offer/publish, cached Taxonomy, Browse comps, business policies. The eBay
variables are live production config, not future placeholders.

**3. Cloudflare R2 was not "not yet built".** `lib/r2-client.ts` reads all five
R2 variables and `routes/flipdesk-images.ts` uses them for the archive endpoint.
