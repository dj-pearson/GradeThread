# Redirect stub registry

When a document moves into the vault, `scripts/vault-move.mjs` leaves a
**redirect stub** at the old path so existing links do not break. Each stub is
recorded here.

Stubs are **transitional**. The end state is one knowledge surface, not a vault
plus a shadow tree of pointers — so US-2065 sweeps this list, deletes every stub
nothing references, and reports the ones that must stay.

## Rules

- A stub is a **pointer only**, at most 5 lines, generated by the tool. A stub
  containing prose is a second source of truth, which is the problem this whole
  epic exists to remove. `vault-lint` enforces the cap.
- Every row here must point at a note that exists. `vault-lint` checks this too.
- Do not hand-edit the table below — `vault-move.mjs` maintains it.

**Swept empty on 2026-07-19 by US-2065.** All 68 stubs were deleted after
their remaining live pointers — 52 references across 44 source, config, CI,
asset and script files — were rewritten to the vault paths.

Sequenced deliberately after the US-2064 benchmark: deleting the stubs is the
irreversible step, so it followed the evidence rather than preceding it.

Historical mentions of the old paths were left alone on purpose. Ralph's
append-only `progress.txt`, immutable migrations, one-off catchup scripts,
`prd.json` story history, test fixtures, and vault notes carrying the
`vault-move:no-rewrite` marker all record where a document USED to live. A
stub is only needed when something LINKS to a path, not when prose mentions
one.
